# מפת היכולות של המערכת הישנה

## בסיס הראיות

המסמך מבוסס על שלושה מקורות שנמסרו לביקורת: Prompt V48, יצוא Node-RED V48 וקוד Apps Script V9. הקבצים נקראו כמקורות תיאור וקוד בלבד; לא בוצעה הרצה מול המערכת החיה. לכן יכולת שמופיעה בקוד מסומנת כקיימת במימוש, אך הצלחתה בפועל אינה נחשבת מאומתת מקצה לקצה.

## מבנה וזרימת עבודה

1. WAHA קולט webhook, מסנן קבוצות, status/newsletter והודעות `fromMe`, פותר מזהי LID ומפעיל allowlist.
2. Node-RED אוגר text, vCard, location, image ו־voice בזיכרון flow ומרכיב batch של הודעות שלא נענו.
3. Apps Script קורא את הרשומה הפעילה מ־Google Sheets. אם יש כמה רשומות פעילות, הרשומה החדשה ביותר נבחרת כברירת מחדל.
4. OpenAI Responses נקרא עם prompt מנוהל, היסטוריה מקוצרת, הרשומה הקיימת ורשימות יישובים/רחובות.
5. שכבות JavaScript גדולות לאחר ה־AI מתקנות ומגבילות את התוצאה: אזור שירות, תמונה, פירוק, קומה, ביטול, אישורים ומוכנות לתיאום.
6. Apps Script מבצע upsert בגיליון; לאחר מכן Node-RED שולח תשובה, הודעות אימות, התאמה, השלמה או התראה למנהל.

## מודל הנתונים הישן

Apps Script מגדיר 28 עמודות בגיליון, ובהן מספר פנייה רציף, טלפון/שם של מוסר ומקבל, יישוב, כתובת, קומה, פריטים, תמונה/מיקום, אישורים, סטטוס, תאריך ונתוני תפעול. המודל שטוח: פנייה אחת היא שורה אחת. הוא נוח לצפייה ידנית אך מתקשה לייצג כמה תמונות, כמה אירועים, כמה התאמות או היסטוריית שינויים ללא דחיסת מידע לתא.

## אמינות ותפעול

- deduplication של webhook נשמר בזיכרון Node-RED ולכן עלול להיעלם באתחול.
- מנגנון batch שומר generation token ומפיל תשובות ישנות, אך גם הוא בזיכרון.
- Apps Script משתמש ב־locks למספר פנייה ולקיבולת, אך אין transaction אחד שמכסה גיליון, OpenAI ושליחת WhatsApp.
- הודעות ותוצאות side effects אינן נשמרות ב־durable outbox. בחלק מהענפים history/flags מתעדכנים לפני אישור מסירה מהספק.
- קיימים retries נקודתיים לקריאת FIND ול־UPSERT, לא מדיניות התאוששות מלאה.
- הלוגים עשירים אך עלולים לכלול תוכן לקוח גולמי.
- prompt מנוהל נשלח לפי IDות prompt, אך ה־flow אינו מצמיד version version; לא ניתן להוכיח שקובץ V48 הוא בדיוק הגרסה שהופעלה בענן.

## יכולות שלא נמצאו ב־MASTER_SPEC

לא נמצא במאגר או בקבצים שנמסרו מסמך בשם MASTER_SPEC. לכן כל יכולת legacy שאין לה מקבילה מפורשת במערכת החדשה מסומנת בהמשך כ־`LEGACY_CAPABILITY_NOT_IN_MASTER`, בלי להסיק שהיעדרה אושר.
