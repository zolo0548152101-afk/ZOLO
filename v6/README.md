# חיים יחד · גרסה 6

וואטסאפ (WAHA) שולח כל הודעה ישירות לסוכן. הסוכן קורא וכותב ל־Postgres ב־Neon, ושולח תשובה בקריאת HTTP ל־WAHA. אין שרת אפליקציה באמצע.

המסד אוכף את כללי העסק. הסוכן לא מעדכן טבלאות עסקיות ישירות.

גרסה 6 רצה על אותו סשן ואותו מספר וואטסאפ כמו גרסה 5: סשן WAHA `HAIM_YAHAD`, מספר `972543414386`. המסד נפרד (Neon, סכמה `haim`). הבעלים מחליף בעצמו איזה webhook פעיל על הסשן. אין לגעת במסד של גרסה 5, ואין להחליף את ה־webhook החי בלי שהבעלים עושה את זה.

## החלת ה־SQL

על מסד ריק (PostgreSQL 16 ומעלה, כולל Neon Postgres 18), לפי הסדר, פעם אחת או שוב. הקבצים idempotent.

```sql
\i migrations/001_schema.sql
\i migrations/002_functions.sql
\i migrations/003_seed.sql
```

אין להריץ את זה על מסד גרסה 5. בפרויקט Neon הקיים (`haim-v6`) מריצים רק אחרי שהמסד עדיין ריק או שזו הסכמה `haim` של הגרסה הזו.

## משתני סביבה

הסוכן:

| משתנה | שימוש |
| --- | --- |
| `DATABASE_URL` | מחרוזת חיבור ל־Neon. הסוכן מריץ דרכה את הפונקציות הציבוריות |
| `WAHA_BASE_URL` | `https://whatsapp-waha.cdpvmq.easypanel.host` (WAHA 2026.8.1 CORE, מנוע WEBJS). בלי סלאש בסוף |
| `WAHA_API_KEY` | כותרת `X-Api-Key` בקריאות אל WAHA |
| `WAHA_SESSION` | `HAIM_YAHAD` |

דף הניהול (Vercel, תיקיית שורש `admin`):

| משתנה | שימוש |
| --- | --- |
| `DATABASE_URL` | אותו מסד. נקרא רק בשרת |
| `ADMIN_PASSWORD` | סיסמה יחידה לכניסה. עוגייה חתומה, בלי מסד משתמשים |
| `WAHA_BASE_URL` | אותו שרת WAHA. ברירת מחדל `https://whatsapp-waha.cdpvmq.easypanel.host` |
| `WAHA_API_KEY` | נשאר בשרת. בלי המפתח אין סטטוס, QR, שליחה ישירה או הורדת תמונה |
| `WAHA_SESSION` | `HAIM_YAHAD` |

אין שירותים נוספים: לא Redis, לא תור, לא אחסון קבצים מקומי. תמונות נקראות מ־WAHA לפי ה־URL שנשמר ב־`messages.media`.

## דף הניהול

```bash
cd admin
npm install
npm run build
```

ב־Vercel: Root Directory = `admin`, Framework = Next.js, והמשתנים למעלה. אחרי הפריסה נכנסים עם `ADMIN_PASSWORD`.

הדף בעברית, מימין לשמאל, באותו מבנה כהה של דף הניהול מגרסה 5 (`src/http.ts` בענף `codex/haim-two-prompts`, חדש יותר מ־`main`). המקור הוא העמוד ב־`/haim-admin`, כולל הסקריפטים שנוספו אחרי ה־HTML הראשון.

## מה לא עבר מגרסה 5

ייבוא גיליונות ותורי pg-boss. וואטסאפ מנוהל ב־WAHA עצמו, והכללים יושבים ב־SQL.

## סיכונים שנשארים

שתי הודעות שמגיעות במקביל, לפני ששתיהן נרשמו בשלב ingest, יכולות כל אחת לקבל תשובה. הנוהל ב־`AGENT_INSTRUCTIONS.md` מקטין את זה: ingest מיידי, המתנה של כשלוש שניות, ואז apply רק להודעה האחרונה שעוד לא עובדה.

אם הסוכן למטה, ההודעות נשארות בלי `processed_at`. אין תהליך שעונה במקומו.

שליחה שסומנה `uncertain` אי אפשר לסמן `sent`. אין לשלוח אותה שוב בלי בדיקה ידנית מול הוואטסאפ.

מזהה הודעה של WAHA הוא מפתח הכפילות. ניסיון חוזר של אותו webhook לא פותח פנייה שנייה.
